Predicting Search Impression Decline for Content Review

FlyRank ML Internship Capstone

This research studies whether historical search-performance and query-mix signals can help identify content items associated with declining search impressions. The goal is to provide a ranked decision-support queue for content review.

Headline result:
The client-grouped Random Forest achieved 83.82% accuracy, compared with 60.85% for the transparent Week 4 baseline on the same held-out clients.

0. Abstract

This project asks whether historical search-performance and query-mix signals can identify content items associated with declining search impressions. The analysis uses the FlyRank ML Internship Warehouse and constructs content-level features from historical search-performance and query-level data. A Random Forest classifier is compared with a transparent Week 4 baseline using a client-grouped validation design. On the held-out clients, the Random Forest achieved 83.82% accuracy and 0.839 weighted F1 compared with 60.85% accuracy and 0.616 weighted F1 for the baseline. The resulting probabilities are used to rank content for human review and decision support rather than to make automatic editorial decisions.

1. Problem framing

The decision supported by this work is which content items should receive priority for editorial review when their search impressions show a decline. The unit of analysis is a content item for a client. The model produces a decline probability that can be converted into a ranked review queue. A human editor can then inspect the historical search and query signals before deciding whether further investigation or content work is appropriate.

A wrong positive recommendation may cause an editor to spend time reviewing content that does not require attention. A wrong negative recommendation may cause genuinely declining content to be missed. ML is useful because multiple historical signals can be combined into a single prioritization score rather than relying only on one hand-written threshold.

2. Data safety

This project uses the FlyRank ML Internship Warehouse release hosted on Hugging Face. The analysis uses daily content-performance data and query-level aggregates. The main modeling frame is built from historical 30-day and previous-30-day windows.

The predictive features are:

  • imp_prev30
  • clk_last30
  • pos_last30
  • visible_queries
  • rare_share
  • anon_share
  • top_query_share
  • ctr_last30

The target is defined using the relationship between last-30-day and previous-30-day impressions. Outcome-derived fields are excluded from the feature matrix to reduce leakage risk.

Pseudonymous identifiers are not used as predictive features. client_hash_id is used only for client-grouped validation. No client names, domains, private queries, credentials, or other identifying information are included in the public analysis.

3. Baseline

The Week 4 baseline is a transparent rule combining recent average position and CTR into a single score:

baseline_score = (pos_last30 / 10) + ((1 - ctr_last30) × 5)

The baseline provides a simple and interpretable benchmark for evaluating whether the machine-learning model adds useful predictive signal.

Metric Week 4 Baseline
Accuracy 60.85%
Macro F1 0.617
Weighted F1 0.616

4. Model / analysis

The final model is a Random Forest classifier. It uses eight historical search-performance and query-mix features. The model contains 300 trees, maximum depth 15, minimum samples per leaf 5, balanced class weights, and random seed 42.

The target is is_declining, defined as an item whose last-30-day impressions are below 80% of its previous-30-day impressions.

The model intentionally excludes imp_last30 and other outcome-derived fields because they would expose information used to construct the target.

5. Evaluation

The final evaluation uses a client-grouped train/test split. The training set contained 71,805 rows from 35 clients, while the test set contained 29,815 rows from 12 held-out clients.

Method Accuracy Macro F1 Weighted F1
Week 4 Baseline 60.85% 0.617 0.616
Random Forest 83.82% 0.826 0.839
The Random Forest improved accuracy by approximately 23 percentage points over the Week 4 baseline on the same held-out clients.

The Random Forest confusion matrix was:

Predicted 0 Predicted 1
Actual 0 8,602 2,247
Actual 1 2,576 16,390

A conventional random split produced 86.51% accuracy, but the client-grouped 83.82% result is treated as the primary validation result because it tests generalization to clients not represented during training.

6. Interpretation

The model indicates that historical search-performance and query-mix signals contain useful information for distinguishing the defined decline outcome. Feature importance provides a descriptive view of which signals the model relied upon most strongly.

These importance values should not be interpreted as causal effects. Correlated features can share predictive information, and the analysis does not establish why a content item declined.

The decrease from 86.51% on the conventional random split to 83.82% on the client-grouped split is expected because the grouped evaluation is more demanding. The remaining performance suggests that useful patterns are not limited entirely to individual rows from the same clients.

7. Recommendation

The model output can be used as a ranked decision-support queue for content review. Editors can begin with high-probability items and inspect their historical search-performance and query-mix signals before taking action.

  1. Prioritize content with high predicted decline probability.
  2. Inspect historical impressions, clicks, CTR, and position.
  3. Inspect query coverage and concentration.
  4. Review before making editorial changes.
  5. Monitor future performance separately after any intervention.
The model is a decision-support tool. It does not prove the cause of a decline, guarantee that an editorial change will improve performance, or predict Google's ranking decisions.

8. Reproducibility

The analysis is implemented in the capstone notebook: work/notebooks/capstone.ipynb. The workflow uses DuckDB for warehouse aggregation and scikit-learn for modeling and evaluation.

The final Random Forest uses 300 estimators, maximum depth 15, minimum samples per leaf 5, balanced class weights, and random seed 42. The client-grouped validation also uses random seed 42.

Credentials are not stored in the repository. A Hugging Face read token is provided through the secure runtime environment when access to the warehouse is required.
